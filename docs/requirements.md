# Shop Service 요구사항 정의서

## 1. 회원 관리 (Member)

### 회원가입
- 사용자는 회원가입을 할 수 있다.
- 회원가입 시 기본 등급이 자동으로 부여된다.
- 로그인 아이디는 중복될 수 없다.
- 이메일은 중복될 수 없다.
- 전화번호는 중복될 수 없다.
- 회원 생성 시간과 수정 시간을 관리한다.

### 회원 조회
- 사용자는 회원 정보를 조회할 수 있다.
- 탈퇴 처리된 회원은 조회 대상에서 제외한다.

### 회원 수정
- 사용자는 회원 정보를 수정할 수 있다.
- 개인 정보는 닉네임과 전화번호를 수정할 수 있다.
- 회원 정보 수정 시 수정 시간이 갱신된다.

### 회원 탈퇴
- 회원 탈퇴는 Soft Delete 방식으로 처리한다.
- 실제 데이터를 삭제하지 않고 deleted_at 컬럼을 통해 탈퇴 상태를 관리한다.
- 탈퇴한 회원은 로그인 및 회원 조회 대상에서 제외한다.


---

# 2. 회원 등급 관리 (Grade)

- 회원은 하나의 등급을 가진다.
- 등급은 구매 금액 기준으로 관리한다.
- 등급별 할인율 정책을 관리한다.

## 기본 등급 정책

| 등급 | 최소 구매 금액 | 할인율 |
| --- | --- | --- |
| BASIC | 0원 | 0% |
| GOLD | 100,000원 | 5% |
| VIP | 500,000원 | 10% |


---

# 3. 공통 코드 관리 (Common Code)

- 시스템에서 사용하는 상태 및 타입 정보는 공통 코드로 관리한다.
- 코드 그룹과 상세 코드로 분리하여 관리한다.

## 관리 대상

- 주문 상태
- 결제 상태
- 배송 상태
- 할인 타입
- 변경 타입


---

# 4. 배송지 관리 (Address)

- 회원은 여러 개의 배송지를 등록할 수 있다.
- 배송지는 회원에게 종속된다.
- 회원은 대표 배송지를 설정할 수 있다.
- 회원의 대표 배송지는 최대 1개만 존재한다.
- 새로운 배송지를 대표 배송지로 지정하면 기존 대표 배송지는 해제된다.
- 회원이 최초로 등록하는 배송지는 대표 배송지로 지정할 수 있다.

---

# 5. 쿠폰 관리 (Coupon)

## 쿠폰 생성
- 관리자는 쿠폰을 생성할 수 있다.
- 쿠폰은 할인 타입을 가진다.

## 할인 방식

- 정률 할인(RATE)
    - 할인율 기준으로 할인 금액 계산
    - 최대 할인 금액 제한 가능

- 정액 할인(AMOUNT)
    - 지정된 금액만큼 할인

## 쿠폰 정책
- 최소 주문 금액 조건을 설정할 수 있다.
- 쿠폰 유효 기간을 설정할 수 있다.
- 삭제된 쿠폰은 Soft Delete 방식으로 관리한다.

## 회원 쿠폰
- 회원에게 쿠폰을 발급할 수 있다.
- 회원별 쿠폰 상태를 관리한다.

관리 상태:
- 발급 완료
- 사용 완료
- 만료


---

# 6. 카테고리 관리 (Category)

- 상품은 하나의 카테고리에 속한다.
- 카테고리는 계층 구조를 지원한다.
- 상위 카테고리와 하위 카테고리를 관리할 수 있다.
- 카테고리 이름을 수정할 수 있다.
- 하위 카테고리가 존재하는 카테고리는 삭제할 수 없다.
- 최상위 카테고리와 특정 카테고리의 하위 카테고리를 조회할 수 있다.
```
예시:
전자제품 
├── 노트북 
│ └── 게이밍 노트북 
└── 태블릿
```
---

# 7. 상품 관리 (Product)

## 상품 등록

- 상품을 등록할 수 있다.
- 상품은 하나의 카테고리에 속한다.
- 상품명, 가격, 재고 수량, 설명을 관리한다.
- 상품 등록 시 기본 상태는 판매중이다.

## 상품 조회

- 상품을 단건 조회할 수 있다.
- 전체 상품을 조회할 수 있다.
- 특정 카테고리의 상품을 조회할 수 있다.
- 삭제된 상품은 일반 조회에서 제외한다.

## 상품 수정

- 상품 정보를 수정할 수 있다.
- 상품명, 가격, 재고 수량, 설명, 카테고리를 수정할 수 있다.

## 상품 상태 관리

- 상품의 판매 상태를 변경할 수 있다.
- 상품 상태는 판매중, 판매중지, 품절 등의 상태를 관리한다.

## 상품 삭제

- 상품 삭제는 Soft Delete 방식으로 처리한다.
- 삭제된 상품 데이터는 보존한다.
- 삭제된 상품은 일반 조회에서 제외한다.

## 상품 변경 이력

- 상품 정보 변경 내역을 관리한다.
- 가격, 재고, 상태 등의 변경 이력을 저장한다.
- 변경 이전 데이터를 보존한다.

# 8. 장바구니 관리 (Cart)

- 회원은 하나의 장바구니를 가진다.
- 장바구니에 상품을 추가할 수 있다.
- 동일 상품은 하나의 장바구니 항목으로 관리하며, 추가 시 수량을 증가시킨다.
- 장바구니 상품의 수량을 변경할 수 있다.
- 장바구니 상품을 삭제할 수 있다.


---

# 9. 주문 관리 (Order)

## 주문 생성

- 회원은 상품을 직접 선택하여 주문할 수 있어야 한다.
- 회원은 장바구니에 담긴 상품을 주문할 수 있어야 한다.
- 하나의 주문에 여러 상품을 포함할 수 있어야 한다.
- 주문 생성 시 주문 번호, 주문 회원, 주문 금액, 배송지 정보를 저장해야 한다.
- 주문 당시의 상품명과 가격을 주문 상품 정보에 저장해야 한다.
- 주문 수량에 따라 상품 재고를 차감해야 한다.
- 재고가 부족한 경우 주문을 생성할 수 없어야 한다.
- 장바구니 상품 주문 완료 시 해당 장바구니 상품을 삭제해야 한다.

## 주문 정보 관리

- 회원은 자신의 주문 정보를 조회할 수 있어야 한다.
- 주문 번호, 주문 회원, 주문 상품, 주문 금액, 배송지 정보를 관리해야 한다.
- 주문 상품별 상품명, 주문 가격, 주문 수량을 관리해야 한다.

## 주문 상태 관리

- 주문의 현재 상태를 관리할 수 있어야 한다.
- 주문 상태가 변경될 때 변경 이력을 저장해야 한다.
- 주문 상태 변경 이력을 통해 주문 처리 과정을 조회할 수 있어야 한다.
- 주문 상태는 주문 생성, 결제 완료, 배송 준비, 배송 중, 배송 완료 등의 상태로 관리해야 한다.

예:
```
주문 생성
   ↓
결제 완료
   ↓
배송 준비
   ↓
배송 중
   ↓
배송 완료
```

# 10. 결제 관리 (Payment)

- 주문은 하나의 결제 정보를 가진다.
- 결제 상태를 관리한다.
- 결제 방식을 관리한다.

관리 정보:
- 결제 금액
- 결제 키
- 결제 완료 시간
- 결제 실패 사유


---

# 11. 배송 관리 (Delivery)

- 주문은 하나의 배송 정보를 가진다.
- 배송 상태를 관리한다.
- 운송장 번호를 관리한다.

관리 상태:
- 배송 준비
- 배송 중
- 배송 완료


---

# 12. 주문 상태 변경 이력 관리 (Order Status History)

- 주문 상태 변경 내역을 저장한다.
- 주문 진행 과정을 추적할 수 있다.
- 변경한 사용자 정보를 기록한다.


---

# 13. 변경 이력 관리 (History)

## 회원 변경 이력
- 회원 정보 변경 내역을 저장한다.
- 변경 전 회원 정보를 보존한다.

## 상품 변경 이력
- 상품 가격, 재고, 상태 변경 내역을 저장한다.
- 데이터 변경 이력을 추적한다.

# 데이터베이스 설계 방향

## Soft Delete
- 회원과 상품, 쿠폰 데이터는 물리 삭제하지 않는다.
- deleted_at 컬럼을 활용하여 삭제 상태를 관리한다.


## Common Code 설계
- 변경 가능성이 높은 상태 값은 공통 코드 테이블에서 관리한다.
- 비즈니스 정책 값은 별도 테이블로 관리한다.


## Snapshot 저장
- 주문 데이터는 생성 당시 정보를 저장한다.
- 이후 상품 정보가 변경되어도 기존 주문 데이터의 정합성을 유지한다.


## History 관리
- 중요 데이터 변경 시 변경 이력을 저장한다.
- 데이터 추적 및 감사 기능을 지원한다.
